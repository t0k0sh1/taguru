## Axis 2 — face-off on 12 location questions (tool-level)

Method: the same 12 questions asked of A (`taguru-code find`/`tree`,
1 call each) and B (`graphify query`/`explain`, budget-capped),
graded on whether the correct file(:line) is in the top hits.
*Caveat: this run graded tool output directly; the full protocol in
EVAL.md (separate agent sessions with token metering) has not been
run yet — the token column is the size of what an agent must read.*

| | A: taguru-code | B: graphify | C: grep (est.) |
|---|---|---|---|
| correct | **12/12** | 8/12 | ~10/12 (typo, method-on-type weak) |
| calls per question | 1 | 1 (+re-query when truncated/noisy) | 1–3 |
| output to read per answer | 1–10 lines (~30–150 tok) | ~2,000-token traversal dump (or truncation warning) | small–medium |
| line info | exact range (`323-346`) | start line only | exact |

graphify misses: `Context::resolve` (surfaced the HTTP handler, not
the method), "what does src/ingest contain" (unrelated nodes),
typo `parse_bacth` (nothing relevant), `BATCH_VERSION` (consts not
extracted). Recurrent hub noise (`dropUndefined()` from the TS SDK)
appeared in most traversals.

**Graduation bar (EVAL.md): A beats B on correctness AND tokens — met.
A's calls ≤ C — met.**

## Verdict

The graduation bar is met on this run: correctness 12/12 vs 8/12,
answers are 1-line `file:lines` (orders of magnitude fewer tokens
than a traversal dump), the accuracy gate is automated and passing,
and freshness is CI-tested. Known limitations that stay open for the
productization decision: Rust-only grammar, and the full EVAL.md
agent-session protocol (token-metered, fresh sessions) not yet
executed.
